# 学术写作子系统架构

## 概述

学术写作子系统将翻译任务中已经保存的过程证据、文献材料和人工记录组织为可追溯的写作工作区，用于生成和修订翻译实践报告草稿。它将证据准备、论证规划、分节写作、验证和审稿拆分为独立阶段，使每个阶段的输入、输出和失效关系可以单独查看。

本文仅说明子系统的组成与数据流。具体报告结构由运行时生成的 `academic-outline.json` 定义，不在本文档中规定。

## 工作流

```text
翻译过程证据
→ 研究模型
→ 文献来源与可定位证据
→ 论证计划
→ 案例选择
→ 写作提纲
→ 分节写作
→ 确定性验证
→ 语义审稿与文献支持审查
→ 定点修订
```

各阶段的职责如下：

1. **翻译过程证据**：从已保存的双语段落、术语决策、审校发现、人工操作和任务统计中整理可引用的项目事实与候选案例。
2. **研究模型**：记录研究问题、理论或方法、分析维度以及输入材料的可用状态。
3. **文献证据**：将导入的来源元数据、可定位文本片段和可使用的文献主张分开保存，避免将书目信息直接视为论据。
4. **论证与案例规划**：将研究问题、项目证据和文献主张关联为论证计划，并选择证据完整且与论点相关的案例。
5. **提纲与写作**：为每个 section 生成范围明确的写作包；写作调用只接收该节所需的主张、案例、引文元数据和统计信息。
6. **验证、审稿与修订**：确定性验证检查可核验关系，语义审稿检查论证与表达，文献支持审查检查主张与来源的对应关系。修订仅重写受影响的 section。

系统可以使用显式标记的合成对照材料辅助分析。此类材料与历史译文分开保存，并保留其生成、诊断和验证记录，避免被误认为真实翻译过程。

## 组件划分

子系统由三个协作层组成：

| 组件 | 职责 |
| --- | --- |
| 证据与候选挖掘 | 汇集项目过程证据、文献材料与候选案例，标记来源和完整性。 |
| 学术编排与状态管理 | 生成研究模型、论证计划、案例选择和提纲，并维护阶段依赖关系。 |
| 写作、验证与审稿 | 生成分节草稿，执行可核验检查、语义审稿、文献支持审查和定点修订。 |

## 持久化产物

所有产物位于 `outputs/<job_id>/`。`academic_state` 记录当前阶段、产物版本、依赖关系、状态和失效原因；大型内容保存在独立文件中，而不直接写入任务状态。

| 产物 | 内容 |
| --- | --- |
| `academic-evidence.json` | 项目段落、过程证据、统计与候选案例。 |
| `research-model.json` | 研究问题、理论或方法、分析维度与输入状态。 |
| `literature-sources.json` | 文献来源元数据与可用状态。 |
| `literature-evidence.jsonl` | 可定位的文献证据片段及其出处。 |
| `literature-claims.jsonl` | 文献主张与支持证据的对应关系。 |
| `argument-plan.json` | 研究问题、项目证据和文献主张之间的论证关系。 |
| `selected-cases.json` | 供分析使用的案例及其选择依据。 |
| `academic-outline.json` | section 的目的、可用证据和允许结论。 |
| `academic-sections.json` | 分节草稿、摘要和写作来源记录。 |
| `academic-validation.json` | 确定性验证结果和警告。 |
| `academic-review.json` | 独立语义审稿结果。 |
| `literature-support-review.json` | 文献支持强度与主张—来源对齐结果。 |
| `academic-repair-history.json` | 定点修订的原因和前后版本记录。 |
| `academic-evidence-warnings.md` | 证据缺口与待人工处理的问题。 |

合成对照材料使用独立产物保存，包括难点机会、模拟基线、错误诊断、优化译文和案例验证结果。

## 状态与失效传播

写作工作区按依赖关系维护产物状态。上游输入变化时，只重建受影响的下游产物：

- 翻译过程证据变化时，重建项目证据及其规划下游；文献来源和已提取的文献证据保持不变。
- 研究问题、理论或分析维度变化时，保留项目和文献证据，失效论证规划、案例、提纲与写作下游。
- 文献元数据变化时，更新来源、引用和写作下游；文献正文或摘录变化时，进一步失效文献证据、文献主张和论证下游。
- 规划、案例选择或提纲实现版本变化时，失效对应规划下游。
- 写作实现版本变化时，仅失效草稿、验证、审稿和修订记录；验证或审稿实现版本变化时，只失效各自的下游结果。

这种分层状态管理支持中断后继续执行，也避免将不同输入条件下生成的内容混入同一份报告草稿。

## 质量控制与限制

系统将可确定性验证与模型审稿分开处理。质量状态由验证和审稿共同确定，可表示为 `pass`、`pass_with_warnings`、`review_required` 或 `fail`。

自动流程可以验证来源身份、证据位置、引用关系、结构约束和部分一致性，但不能替代人工学术判断。使用时仍应重点核对以下内容：

- 文献来源和元数据是否完整、准确且允许使用；
- 引文是否忠实表达原始材料；
- 案例分析是否基于实际记录，而非推断的过程或意图；
- 理论解释、研究结论和最终提交文本是否符合任务要求。

对于历史任务中未保存的初译、术语注入或修订记录，系统只能报告证据缺口，不能追溯补建。
